Every new conversation stayed at **Thinking…** and never reached its provider. The stuck Claude session sat at `starting` with no provider process: `Core.sendTurn` was waiting for memory recall. One graph-memory worker thread had run near 100 % CPU since about 09:50, reading `memory.sqlite` at nearly 5 GB/s with no writes, and had used 79 minutes of CPU by 11:15. A Forget or Clear in Project memory at 09:50 had started an erasure preview. Its walk re-entered the erased history the October 10 expiry loop left: 96,805 erased claims, artifacts and payloads and 290,415 lineage rows. The walk's lookups had no index, so each step scanned whole tables. The worker serves one request at a time and a turn waited for recall without a deadline, so every turn queued behind the walk.

- **Erasure walk.** Migration 3 indexes the columns the walk looks records up by, and the columns that reference a payload, so deleting one never scans a table. The walk skips tombstoned records, whose descendants were erased with them. It collects a selected record's supporting sources in one query, and closures use set membership. An erasure reuses the preview computed just before it while nothing has committed, and skips targets an earlier job already scrubbed.
- **Budgets and cancellation.** Forget previews and the source lookup before an erasure stop after 30 s, and retention expiry after 60 s, never inside a transaction. An accepted erasure has no budget, so its replay at startup can always finish. Cancelling a request sets a second slot in its shared cancellation buffer, which a running walk checks at each step.
- **Watchdog.** The worker announces each request it starts. A request that runs past its limit ends the worker. The limit is one minute beyond its budget, ten minutes for an erasure or expiry that may be committing, and none for backup, restore, rebuild or compaction. The open transaction rolls back, waiting requests fail, and a new worker replays any recorded erasure that never committed. Closing gives a busy worker five seconds. A housekeeping tick now catches its own errors, which would otherwise have been unhandled rejections in the broker, and `health` reports them as `maintenance_error`.
- **Turns.** A reply waits at most eight seconds for memory, then continues without recalled context and marks memory degraded; Stop still ends the wait at once. Meanwhile the session's activity is `recalling`, shown as **Recalling memory…** in the conversation, the Activity Panel and the session list. The portrait, the emoticon and the pet's pose treat it as thinking, and Cere Mobile's source has the label too. Housekeeping yields while a turn recalls.
- **Compaction.** `cere memory compact --output PATH` writes a backup and manifest to a new path, then in the same worker call removes tombstoned claims, artifacts and payloads with their support and lineage rows, finished projection jobs, and change records of tombstoned targets that every projection has passed. ## Memory citation display toggle — October 12, 2026

Replies that use recalled memory cite it as `[evidence:ID]`. **Settings → Memory → Show memory citations in replies** (`showMemoryCitations`, off by default) now keeps those markers out of everything a reply is shown in or copied from. Stored replies keep them: `broker/memory.ts` still reads the cited ids from the saved answer for `record_response`.

- **Rules.** `broker/citations.ts` and `native/citations.h` apply the same rules and are both checked against `tests/fixtures/memory-citations.json` (35 cases). A marker takes the space before it when punctuation or the end of the line follows, and the space after it at the start of a line; parentheses or backticks that only wrap it go too. Comma or semicolon lists and adjacent brackets count as one marker. A line left with only a list marker or a label such as `Evidence:` or `**Sources:**` is removed without doubling a blank line. ## Practical coverage limits

The local desktop has three monitors, all currently at scale 1. Dragging and output placement were exercised on this desktop. Mixed-DPI physical displays, physical monitor unplugging, suspend/resume, and screen lock were not exercised. Layer-shell places Cere over application windows; it does not override security surfaces or guarantee ordering against unrelated overlay applications.

Linked terminal sessions expose lifecycle and navigation only. Existing CLI transcripts can be selected for explicit handoff after their terminal writer stops. Claude history discovery reads a bounded subset of recent JSONL transcripts and can skip unknown formats. Native provider transcript history is preserved for resumption, while Cere’s visible transcript starts with the messages it has observed.

MCP forms support primitive values. URL sign-in requests show their HTTP(S) destination and need explicit confirmation; other URL schemes are declined. Unsupported complex forms fail closed and request terminal continuation. A broad Cere grant does not override the provider’s own permission requirements.

A final 60-second sample with the updated pet visible and no active CLI task measured 1.98% of one CPU core across Cere's three processes. Proportional set size was 216.8 MiB; summed resident set size was 356.2 MiB (including shared library mappings counted in multiple processes). Resource evidence: `/tmp/cere-animation-resources.json`. The earlier sparse GIF loop measured 0.15% CPU, 199.4 MiB PSS, and 331.2 MiB summed RSS. Smooth transforms and more detailed cached artwork increase resource use; summed RSS remains above the original 200 MiB budget. Static holds avoid continuous rendering, and hidden/quiet/reduced-motion hosts stop their animation timers.

Performance budgets are not guarantees across hardware. No cross-platform support claim is made beyond this Hyprland setup.
