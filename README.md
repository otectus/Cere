# Cere

[Download Cere Mobile 0.1.5 for Android](https://github.com/otectus/Cere/releases/download/mobile-dev-v0.1.5/cere-mobile-v0.1.5-dev.apk) · [Development release and checksums](https://github.com/otectus/Cere/releases/tag/mobile-dev-v0.1.5)

This development APK updates an existing `.debug` development install in place, keeping its pairing, encrypted cache and drafts; do not uninstall it first. It adds the redesigned phone interface, safer cross-device draft reconciliation, and the reviewed adaptive Cere launcher icon, while retaining protocol 1.1 and pairing without copying. Run it with the matching Cere 0.1.5 desktop broker. Android 11 or newer is required; the launcher was checked on Android 11 and Android 15. This development channel uses the debug package and development signer. A future stable mobile release is a separate install and still requires the owner's permanent signing key and the physical-device evidence gates ([release details](docs/mobile/RELEASES.md)). See [mobile setup](docs/mobile/SETUP.md) for pairing; the [feature matrix](docs/FEATURE-MATRIX.md) lists what the phone and the desktop each offer, and why anything stays on the desktop.

Workspace telemetry is available as an opt-in Linux feature under Settings.
See [setup, privacy boundaries, shell hooks and measurements](docs/workspace-telemetry.md).

Cere 0.1.5 is a native desktop companion for Arch Linux and Hyprland. It runs Codex, Claude Code, AntiGravity, Ollama and API conversations. Its [Workbench](#workbench-files-images-and-analysis) lets Ollama and API conversations work with real files, images and isolated analysis runs. Changes to your files are applied only after you review them, or within an edit permission you grant. [CHANGELOG.md](CHANGELOG.md) lists what changed in each release. Click Cere for chat and desktop controls; drag her to move. Twenty-four selectable avatars use their front-view reference artwork, connected full-body gesture frames and registered eyelids. Reduced motion preserves each original still pose. Always-on-top is enabled initially, including above fullscreen application windows. Disable it for normal floating-window behavior.

## Run from this workspace

```sh
./tools/run.sh
```

Use `./tools/run.sh --show` to open the expanded workspace immediately. The tray opens or hides Cere and offers separate quit options for stopping sessions or leaving them running. Only one interface instance runs per runtime directory.

In Dolphin, right-click the background of a local folder (or one folder) and choose **Start Cere Conversation Here**. The installer adds this menu action; it opens **Start a conversation** with the project folder filled in. Review your provider and settings, then open the conversation. The command-line equivalent is `cere --new-conversation /path/to/folder`.

Build the application first using the instructions below. Generated binaries, local dependency bundles, user state, and credentials are not included in the repository. If `.local-deps` is present locally, `tools/run.sh` configures its library paths.

## Build and install on Arch

Local speech uses bundled Piper and `en_US-amy-medium`. Install Python 3.12+,
`alsa-utils`, `sox` and `pipewire-alsa` (or PulseAudio's ALSA plugin) alongside the build
dependencies below. The first build downloads checksum-pinned speech assets. Two
ONNX Runtime license texts are kept in `packaging/licenses/` instead, because their
upstream repository is no longer published. Installed playback is offline. See [voice settings, `/tts-test`, custom voices and
Speech Dispatcher setup](docs/tts.md).

Voice settings also offer **ElevenLabs · API**, with a private API key, account
voice/model selection and streamed playback. **Speak replies from** lets you
enable automatic speech separately for each conversation provider, including
pinned conversations. See [voice and API setup](docs/tts.md#elevenlabs-api-speech).

**Settings → Voice → Speech provider → IndexTTS** adds optional local voice cloning,
multilingual IndexTTS-2.5 and an optional IndexTTS-2 checkpoint. Its pinned Python,
Torch and model files live in an isolated per-user runtime. Review the license
before downloading; allow about 30 GiB for setup. See the [IndexTTS installation,
voices, hardware limits and troubleshooting](docs/tts.md#indextts-voice-cloning).

Install `base-devel cmake ninja qt6-base qt6-declarative layer-shell-qt nodejs npm`. Desktop controls additionally use `hyprland gtk3 xdg-utils wireplumber libnotify grim satty systemd`. Qt 6.8 or newer is required for the avatar renderer. Node 24.22 or newer is required; CI pins 26.8.2 (see `.node-version`). The full test suite passed on Node 24.22.0, 26.8.2 and 26.11.1 on October 20, 2026, and on 26.13.1 on November 20, 2026. Graph memory additionally requires Node’s linked SQLite to be 3.51.3 or newer with FTS5; startup rejects an older SQLite build. Install and authenticate Codex CLI and Claude Code separately; Cere uses those installed executables and their own authentication/configuration.

The Workbench optionally uses these packages:
- `bubblewrap` for isolated Code Lab runs and commands;
- `ripgrep` for regular-expression search;
- `poppler` for PDF text;
- `tesseract`, with language data such as `tesseract-data-eng`, for OCR;
- `python-numpy` and `python-matplotlib` for Code Lab charts (Code Lab runs the system `python`).

The package lists them as optional dependencies; Tesseract also needs a language data package. A missing one makes only its feature unavailable, and Cere reports it rather than failing. The build compiles the Workbench's file helper, `cere-workspacefs`, with the toolchain from `base-devel`.

```sh
npm ci
npm run build
npm test
npm run typecheck
makepkg -si
```

The package installs `cere`, its desktop entry, and `cere-broker.service`. The installed UI starts the user service on demand, and starts it again if the broker stops while Cere is open. Login startup is opt-in in **Settings → Companion**. It adds an XDG autostart entry, which Hyprland runs only when the session processes autostart entries, for example through UWSM or `dex -a`. Removing the package preserves user data.

For a per-user installation after building, run `python3 tools/install-user.py`. This installs the application, menu entry, icon and user service beneath `~/.local`, and preserves an existing login-startup preference. When local build dependencies were used, it bundles LayerShellQt; base Qt and Node remain system dependencies. No project-folder launcher is needed. Use `--prefix build/user-install` to stage and inspect the installation first. Open **Cere** from your application menu, or run `~/.local/bin/cere --show`.

After installation:

```sh
cere                 # show the pet
cere show            # open the full workspace
cere toggle          # toggle the compact panel, starting Cere if needed and recovering a hidden pet
cere terminal codex  # register a terminal session, then run the normal CLI
cere terminal claude
```

Use your compositor’s configuration interface to bind `cere toggle` to a convenient shortcut. Cere does not replace your existing keybindings. The legacy Hyprland configuration equivalent is `bind = SUPER, C, exec, cere toggle`; newer Lua-based configurations use their own binding syntax.

## Interaction

- Click Cere to open her compact panel; the message box is ready for typing as soon as it opens. Dragging suppresses the click. Right-click for size, roaming, quiet mode, and visibility. With always-on-top disabled, the compact panel is a normal window that Hyprland floats beside her at its compact size.
- On short screens the compact panel folds **Model**, **Handoff**, **Inbox**, **Memory review** and **Context** into a **More** menu beside Send, and the conversation page scrolls rather than hiding controls, so every part of the panel stays reachable.
- Chat supports streaming replies, selectable CommonMark/GitHub Markdown (headings, emphasis, nested lists, task lists, tables, links, images and fenced/indented code), image attachments, Stop, and provider approvals. Tool activity stays in the expandable **Activity Panel** below the conversation; click its bar again to hide it. Enter sends (Ctrl+Enter works too) and Shift+Enter starts a new line; Ctrl+N creates a session; Ctrl+K opens the command palette; Ctrl+, opens Settings; Ctrl+Shift+W opens or closes the Workbench; Escape closes the Workbench when it is open. From another page it returns to the conversation; otherwise it closes the panel.
- Codex and Claude questions appear as dedicated forms with option descriptions, single or multiple selections, and written answers. Required answers are checked before submission. Desktop question drafts survive navigation and unrelated progress updates in the same UI process; private answers are masked and redacted from Cere's conversation history. Permission bypass never supplies an answer.
- **Activity** shows native subagents and delegated conversations, including their current task, progress, result, and interruption or failure. Active agent counts remain visible when the panel is closed. Parent conversations stay busy while tracked background work remains, and child replies stay in Activity. Claude Code's reply after its background work finishes belongs to the same turn. A delegated Codex or Claude task reports back by itself: when it finishes, its parent conversation shows a **Delegation update** card and takes an automatic turn to summarize the result (see [orchestration](#ollama)). Stop includes active child work.
- Expand opens an ordinary resizable workspace. Selecting a session restores its draft. Moving between the compact panel and the workspace keeps the draft and its attachments, the cursor and selection, the **Search web** choice, the Activity Panel and the message you were reading, even though the two windows lay the conversation out at different widths. New output does not force scrolling while you read earlier messages, whether you scroll with the wheel, by dragging, or with the scrollbar.
- New sessions offer Codex, Claude Code, Ollama, AntiGravity, OpenAI API, Claude API, Google AI API and a compatible endpoint (see [AntiGravity and direct APIs](#antigravity-and-direct-apis)). CLI model and effort dropdowns use each provider’s catalog; their default choices retain the CLI’s settings. Ollama offers its available chat models and a saved default. Ollama and the compatible endpoint can use a saved connection instead of the one in Settings. Ollama and API conversations can turn on the Workbench's **Files**, **Images** and **Analysis**. Tick **Save as my defaults** as you open a conversation and the next one you start from **New session** opens with the same provider, model, effort, desktop tools and temporary choice. Titles, folders and trust are chosen each time; projects keep their own defaults, and delegated, branched, imported and phone-started conversations never use these.
- When both Cere windows are closed or minimized, pending permissions appear in a speech bubble beside the visible pet, with the same response buttons and session labels as the workspace. Every request names its provider and session ID, the full session title and the project folder on separate lines, so a long title never hides which project is asking. The bubble remains available in quiet mode and disappears when requests end or a Cere window opens.
- Sessions creates managed conversations or imports completed CLI history. Confirm that the external session is stopped before resuming it. The terminal launcher only reports lifecycle and offers terminal navigation; it does not scrape or remotely type into the terminal.
- Handoff lets you choose another provider and creates an editable draft using recent conversation text. Nothing is sent until you review and submit it.
- Desktop groups controls into responsive cards, with category filters and search across actions, applications, and windows. It launches applications, opens files/folders, focuses or moves windows, changes workspaces, controls media and live output volume, opens captures in Satty, creates timers, and runs saved executables with explicit arguments. Long names have tooltips; every section remains reachable by scrolling in the compact panel.
- Capture in Satty opens the focused display in the crop/annotation editor. Enter saves the edited image and returns to Cere’s preview; Escape cancels. The temporary original is removed. An explicit sharing choice precedes giving an AI session the saved image.
- Media controls prefer Spotify when it is open, otherwise the playing MPRIS application. Cere displays the target and playback state, pins button commands to that target, and disables unavailable actions. Closing the target does not silently redirect an in-flight button press to a browser.

Roaming starts disabled. When enabled, Cere slowly follows the mouse across your displays, easing into motion at up to 75 logical pixels per second and stopping short of the pointer. Small pointer movements do not make her shuffle constantly. Hovering or using her menu, opening either interface, a reply, completion or approval bubble beside her, dragging, fullscreen apps, task activity, hiding, quiet mode, and reduced motion pause following. The old roaming-area presets are replaced by following across the available screens.

All twenty-four avatars have six full-body routes: wave, thinking, open-hand presentation, celebration, a timid blush with both hands against the cheeks, and a dangling/flailing pickup loop. Their original front-view reference supplies the resting pose. Generated gesture frames preserve the character’s clothing, colors and silhouette, with uniform scaling and room for extended hands. Standing gestures keep their feet planted; carried poses bend their knees and swing their feet freely. The source sheets and generation prompts live locally under `artwork/avatars/{id}/`, outside version control.

![Cere in her six gestures: wave, thinking, open-hand presentation, celebration, timid blush and the pickup flail, each with its expression badge](screenshots/gestures.png)

Animation follows Qt’s display animation clock. Each route contains 51 prepared frames, played at 60 Hz. Standing gestures hold their endpoint and return through the same frames. Hovering raises the hands into a gentle blush; clicking deepens the same sequence and opens or closes chat. The stronger reaction eases back to the hover pose while the pointer remains over the avatar. Dragging beyond the click threshold starts an alternating flail loop, with pendulum motion around the actual grab point and a softened shadow; releasing eases back into a standing pose. Interruptions reverse from the current frame before entering the latest requested gesture; an old gesture cannot jump back in after a newer request. Continuous breathing, restrained sway, attention and carrying/landing motion apply to the connected figure. Output-seam mirrors consume the primary avatar’s exact sample. Native GPU and software rendering use the same registered artwork, bounded lazy image caching and area-averaged textures for small desktop sizes.

The 76-clip catalog controls intent, priorities, timing and subtle movement. Nineteen clips select the six illustrated routes; the other clips use shared gaze, tilt, sway and other secondary movement rather than separate limb drawings. Hover and click reactions can play during ordinary task activity, while approvals, errors, disconnects and dragging take priority. Focus in a chat draft means listening; live provider activity distinguishes thinking, replies and tool work. Permissions and problems take priority, and confirmed completion can celebrate. Idle energy, intensity and mood still control automatic acting. Automatic blinks use registered closed-eye frames at rest and gesture endpoints, avoiding a neutral face being pasted over a moving pose. Winks close one visible eye; Witty’s fixed mint X and Rem’s covered eye remain unchanged. An automatic blink already in progress finishes smoothly when another eye animation starts. **Settings → Motion & expressions** includes previews, including **Timid blush · hands to cheeks**. Reduced motion, zero intensity and quiet mode use the original still pose. Hidden avatars stop their animation clocks. Speech is configured independently under **Settings → Voice**.

The compact panel and workspace headers use a dedicated twelve-frame head portrait, with neutral blinks, subtle head movement, pointer attention and a click-to-wink greeting. Other moods keep their expression because the atlas has only one neutral closed-eye portrait. Connection problems, permissions and task activity take priority. A small speech indicator follows actual voice playback. Quiet mode, reduced motion and zero intensity stop the portrait's animation; hidden and minimized windows stop its animation clock.

The portrait estimates the tone of Cere's current English replies locally, using weighted phrases, negation, contrast, recent clauses and expressive punctuation. It excludes tools, code and quotations, fades old replies and resets when you switch conversations or send a new message. Short holds smooth changes during streaming. Ambiguous, unsupported-language and over-12,000-character replies stay neutral. This is a best-guess expression, not a reliable interpretation of sarcasm or proof of task success. **Respond to conversational tone** disables it independently of activity expressions. The portrait and full body consume one settled QML mood source, shared between UI and overlay hosts through attention updates. The existing 650 ms hold for competing non-neutral moods remains; body reactions occur at most once every six seconds. Busy activity, permissions, problems, disconnects and dragging take precedence, and blocked reactions are discarded rather than queued. The tone toggle governs both reactions and idle tinting. Conservative opening-phrase matching remains for user support and as a fallback if the shared QML source is unavailable; it never overrides a valid neutral classification. Mood-weighted selection favors matching gestures among the remaining bag entries (3:1) without duplicating entries or inventing task success. Each avatar uses `assets/{id}-portraits.png`; its built-in imagegen prompt is kept with the local source art under `artwork/avatars/{id}/`.

Mood behavior is authored in `motions.json → bodyMoods`. Life multipliers below apply relative to the selected idle profile; unlisted channels stay unchanged. Preferred gestures bias order within the bag, not the total number of appearances across a complete bag.

Animation authoring separates reference registration, gesture intent and rendering:

- `assets/avatars.json` is the authoritative avatar manifest. Every entry supplies `id`, `label`, `description`, `themeLabel`, `portrait`, `rig`, `default`, `aliases`, `palette` and `authoring`. Exactly one entry is the default; aliases preserve old saved IDs (`cere` resolves to `cere_default`). `palette` contains the shared color tokens; `authoring` contains reference crops, visible-eye registration, sheet ordering, portrait packing and any reviewed pose landmarks. `broker/avatars.ts` defines and validates the schema. The build checks every entry and its runtime assets. The broker, native startup, themes, Settings/command-palette search, mobile portraits and catalog-wide tests derive their entries from this file; there is no startup ID allowlist or second palette registry.
- To add an avatar, provide its reference and authored sheets, packed `assets/{id}-surface.png`, `assets/{id}-surface-rig.json` and `assets/{id}-portraits.png`, then add one conforming manifest entry. The three `tools/prepare-avatar-*.mjs` tools read its `authoring` settings there. Local source PNGs, prompts (including `carry-sheet-prompt.txt`) and generated registration remain under ignored `artwork/avatars/{id}/`; the former `artwork/avatars/sources.json` is no longer read. Missing local source images still cause source-pixel checks to skip; shipped atlas/frame checks do not need them. Do not treat those skips as source-art validation.
- The shared `assets/cere-rig.json` retains the motion channels and stance definitions. Each manifest-selected surface rig registers its neutral and closed-eye cells, gesture frames, endpoint blinks and route mappings without changing painted aspect ratios. Registration supports one visible eye when a fringe covers the other, as for Rem. The preparation tools share silhouette separation for uneven gesture and portrait grids.
- `assets/motions.json` owns clip priorities, timing, idle profiles, blink cadence and mood reactions. `qml/Motion.js` samples continuous acting; `qml/SurfaceMotion.js` handles frame travel, holds and interruption recovery. `qml/GesturePlayer.qml` combines them on one clock.
- `native/avatarpuppet.cpp` validates atlas geometry and lazily prepares the selected frame for GPU or software rendering. At startup the interface checks the catalog from each atlas's PNG header without decoding it; the build's asset checks decode every atlas. If the shown avatar's artwork then cannot be drawn, a full load confirms the failure before that avatar is set aside, and the next usable one is shown with a notice. The desktop hit region includes every gesture silhouette. Each avatar's local `artwork/avatars/{id}/registration.json` records the source position, scaling and foot anchor used by the preparation tools.

After authoring, run `tools/test-virtual-desktop.sh node --test tests/avatar-surface-motion.test.ts tests/avatar-animation.test.ts tests/assistant-identity.test.ts tests/avatar-settings.test.ts` and `tools/test-virtual-desktop.sh ctest --test-dir build -R '^(avatar-registration|motion|avatar|avatar-software|qml)$' --output-on-failure`. The asset checks verify original visible pixels, frame bounds, planted standing gestures, free carried feet and unclipped silhouettes across all twenty-four characters. `cere-ui-check connectedSurfacePoses` checks gesture playback, interruption, reduced motion and input regions at two scales. `cere-ui-check avatarPointerReactions` checks both desktop sizes and covers hover, stronger click, the drag threshold, carrying, release and urgent-state priority. Set `QTEST_FUNCTION_TIMEOUT=900000` for these full-catalog UI sweeps. Run acceptance checks through `tools/test-virtual-desktop.sh COMMAND [ARGS...]`. It creates a private headless Hyprland session with separate profile, sockets, session bus, network and process namespaces; physical input devices and the working desktop are inaccessible. Pointer acceptance uses the virtual session’s Wayland pointer protocol for compositor button grabs, motion and release. It never creates a system-wide mouse. The wrapper requires Bubblewrap, an xdg-shell v6-capable Cage parent, Hyprland and a GPU render node; `CERE_CAGE_BINARY`, `CERE_RENDER_NODE` and `CERE_VIRTUAL_EVIDENCE` configure local dependencies and evidence paths. See `VALIDATION.md` for the validated local setup. `CERE_POINTER_EVIDENCE_ROOT` optionally separates pointer captures from other runs. Review captures from the virtual desktop as well: passing numeric checks does not establish visual quality.

## Sessions, workflows, and companion tools

- **Ctrl+K** opens unified navigation for sessions, folders, projects, settings, saved actions, transcript matches, bookmarks, and decisions, with favorites and recent commands. **Ctrl+N** opens a conversation; **Ctrl+,** opens settings. Settings search and interface scaling work independently of pet size.
- **Settings** shows one category at a time, grouped under Cere herself (Companion, Personality, Voice, Motion & expressions), Assistant (Connections, Knowledge, AI assistance, Saved scripts) and System (Cere Mobile, Workspace telemetry, Application): in a rail beside wide pages, or a scrolling strip of chips on narrow ones. **Find a setting** searches individual settings; Enter or a result opens its category, scrolls to the control, focuses it and outlines it briefly. Escape clears the search first. **Ctrl+K** lists the same categories and settings, and Desktop's **Manage scripts** opens Saved scripts.
- **Sessions → New folder** creates an organizational folder. Rename it, move sessions between folders or back to Unfiled, pin, archive, and filter by working directory or unread status. Deleting a folder preserves its sessions. Folder membership never changes a project path, permissions, or memory scope. **Delete…** in a conversation's context menu (right-click or Shift+F10) removes it after confirmation, together with its transcript, draft, attachments, queued messages and workflow results. Cere refuses while the conversation is working, waiting for an approval or running a power session. Project memory is kept. Temporary conversations offer **Discard…** instead.
- The composer supports reviewed file/image attachments with previews and individual removal, drag-and-drop, explicit clipboard import, revisioned draft recovery, quote-to-reply, and message bookmarks. In Ollama and API conversations, type **@** to reference Workbench files, folders, conversation files, collections or other conversations in the project (see [Workbench](#workbench-files-images-and-analysis)). Private attachment copies are removed once no draft, uncertain submission, or active turn needs them. **Context** shows attachments, destination, rough text usage, and recent memory evidence; native CLI history and filesystem access remain additional context Cere cannot fully measure.
- **Branch** creates a new conversation with selected, editable context. A separate Codex native-fork option requests an actual provider history fork and reports failure if unsupported; it never silently substitutes a text copy. Temporary conversations retain Cere transcript/drafts only in memory and exclude durable workflows, memory, and mobile access. They currently accept text only; external providers retain their own policies.
- **Project workflows** provides editable, revisioned capsules scoped to the exact project directory. Resuming creates an editable draft from the reviewed capsule. There are sixteen built-in recipes, all with typed inputs, pinned instructions, versioned definitions, exact previews, a one-turn limit and a 30–600 second deadline. A recipe draft is sent only when you send it, or when a schedule you created for it runs. Substantial edits remain in the chosen editor. Eight are Workbench recipes, which take a folder, file, conversation file or collection that you pick rather than type; a Workbench recipe's draft gets only the folders you referenced, with the permissions they already have. The Workbench recipes are:
  - Explain this project
  - Review configuration change
  - Folder cleanup plan
  - Document briefing
  - Image asset kit
  - Screenshot to issue report
  - Data to report
  - Release materials
- The result hub separates provider completion from verification, links observed artifacts and transcript evidence, and can run an explicitly reviewed saved check in the result’s project. Only its observed exit code establishes that check’s pass/fail; it does not certify the whole task.
- **Memory review** proposes decisions or constraints from a message with its supporting passage and source role visible. Confirm, correct, keep local, or discard the proposal. Existing inspector correction/forgetting controls remain available inline, including **Why was this recalled?**.
- Local push-to-talk records at most 60 seconds into a private temporary file and uses a user-configured local transcription executable/model. The transcript enters an editable review before the composer; there is no always-listening mode or automatic model download. Speech supports selected-text playback, rate adjustment, and an optional brief reading that preserves the full written response.
- **Offline tools** provides notes, tasks, arithmetic, conversions, and pause/resume/repeating timers. Reviewed workspace routines use exact previews; undo is offered only for created timers. Focus, Gaming, and Presentation profiles combine visibility, speech, animation and ordinary notification preferences while retaining approval access. Home positions are per monitor; edge docking is explicit.
- **Health and recovery** (**Settings → Application → Maintenance**, beside **Backup and restore**) distinguishes provider/authentication/protocol/network, memory, and speech problems. It names desktop programs that are missing and the feature each one affects (**Unavailable until installed**; chat is not affected), and says when the previous stop could not confirm that everything Cere was running had finished. Diagnostics use an allowlist and must be previewed before export. Reviewed backups exclude by default credentials, device keys, active grants, executable actions, temporary conversations, and Workbench folder access, pending file changes and image or analysis runs. A backup with conversations can also hold their conversation files, with or without their contents; a restore checks every file's hash and tells you how many come back without their contents. Restore preserves the current forgetting registry, pauses tools, marks restored sessions interrupted, and never replays a turn. If forgetting records differ, old conversation, draft, attachment, file and notes payloads are omitted conservatively. Restoring keeps this computer's connections (saved connections included), API and image-backend keys, paired phones, voice profiles, personality and other preferences. It clears project grants until you resume tools. Conversations, drafts, notes and project capsules come from the backup only when it includes them; a backup without them restores a profile without conversations. Restoration stages a new profile and restarts the broker (through `cere-broker.service` when installed); the previous private profile, including its conversations, is retained.

## Workbench: files, images and analysis

Saved Ollama, OpenAI API, Claude API, Google AI API and compatible-endpoint conversations can work with real files, images and isolated analysis runs from the **Workbench**. Open it with **Ctrl+Shift+W**, **Workbench** under the composer, or the command palette. Its tabs are **Files**, **Preview**, **Changes**, **Images**, **Runs** and **Shelf**. It sits beside the conversation in the workspace and becomes one sheet with a way back in the compact panel.

The **Files**, **Images** and **Analysis** switches decide what the model is offered; you can always use the Workbench yourself. The **Review** and **Plan** postures withhold changes, images and analysis. Temporary and phone-controlled conversations stay text-only.

- **Folders and reviewed changes.** A conversation can have up to eight folders, or a private conversation workspace. Each folder sets:
  - whether files may be created and edited;
  - whether they may be organized (folders, copy, move and trash);
  - whether hidden files are listed;
  - whether approved commands may run there;
  - which models may process its contents (models on this computer by default).

  Files are opened through a confined helper, `cere-workspacefs`, which refuses `..`, symlinks and paths outside the folder. Proposals from the model or from the Preview editor open in **Changes** with their diffs. Accept all, accept a selection, or reject. A file that changed after the proposal is refused rather than overwritten, and results are shown per operation. **Undo…** creates a new review and never overwrites a newer edit; trashed files are kept privately. A folder's **Edit permission** allows small text edits for a set time and number of operations without asking each time.
- **References with @.** Type **@** in the composer to reference a file or folder, a conversation file, a file shared with the project, a bound collection, or another conversation in the project. References are resolved and authorized at send time, never read from paths in your text:
  - a folder adds its list of entries, not its contents;
  - a changed file is used as it is now, with a note that it changed;
  - a source the model's destination may not receive stops the send, with the reason.

  A line under the chips previews what the references add.
- **Conversation files and documents.** Imports, images, extractions and run outputs are kept as immutable, hashed versions you can pin, share with the project or save anywhere. An export into a workspace folder is a reviewed change that never overwrites. Removing a file can also remove what was made from it. Documents are read with locations: PDF pages (poppler), DOCX paragraphs and tables, XLSX cells with formulas and cached values, CSV, JSON, XML and HTML. Macros never run, external links are never fetched, and scanned pages are reported so you can use OCR. A recording transcribed from a file also keeps a timestamped WebVTT transcript.
- **Images.** Set up backends in **Settings → Connections → Images & analysis**:
  - **OpenAI** and **Google** image APIs use your API keys. The first request asks you to acknowledge billing, and a daily budget applies. The assistant asks before each image job unless you allow it to start them.
  - **ComfyUI** runs on your own server. Imported workflows are reviewed, and **Test** reports missing nodes and models.

  **Create image** works whatever the chat model can do. The editor crops, annotates, masks, compares, resizes and converts; every result is a new version and originals never change. **Keep pixels outside the selection unchanged** composites masked edits. Jobs appear in **Runs**. A job whose outcome is unknown is never resent automatically, and a ComfyUI job is checked by status after a restart. Low-memory mode runs one local GPU job at a time.
- **Vision, OCR and the review helper.** A vision helper answers questions about an image for a model that cannot see. OCR uses Tesseract on this computer. The review helper is a second model for narrow reviews (summarizing documents, reviewing a pending change set, summarizing research); it gets only the chosen inputs, has no tools and changes nothing. Files and images are never sent to a helper whose destination their permissions do not allow.
- **Code Lab, commands and Git.** With Code Lab turned on in Settings, Python runs inside bubblewrap without network access, on read-only copies of the chosen conversation files. Only files written to its output folder are kept. **Runs** shows which limits are enforced on this computer. Commands in a folder always ask. Git inspection is read-only, with hooks and external diff programs disabled. Without isolation, Code Lab and commands are reported as unavailable rather than run unconfined.
- **Shelf.** The project shelf lists:
  - shared and pinned files;
  - bound collections;
  - the capsule's accepted decisions and tasks;
  - other conversations in the project;
  - saved recipes.

  **Use in next message** adds a reference; nothing on the shelf enters a prompt by itself.

The permission-skip switches never approve Workbench change reviews, image jobs, analysis runs, exports or vision-helper requests. Only the Workbench's own permissions skip those questions: a folder's edit permission, a Code Lab grant, or letting the assistant start images within its daily budget. Phones see Workbench cards as text in Activity; folders, files, images and runs stay on the desktop (see the [feature matrix](docs/FEATURE-MATRIX.md)). [The Workbench guide](docs/WORKBENCH.md) covers setup, each tab, optional packages and recovery.

## AntiGravity and direct APIs

**New session** offers **AntiGravity**, **OpenAI API**, **Claude API**, **Google AI API** and a **Compatible endpoint** alongside Codex, Claude Code, and Ollama. They also appear in reviewed handoffs and branches. A paired phone can start and continue the API conversations once it holds `providers.api` and that provider's grant (see [mobile setup](docs/mobile/SETUP.md#manage-access)); its requests use this computer's keys and may be billed. AntiGravity turns start only on the desktop, because its headless mode cannot prove restricted execution; the phone can still read those conversations.

- **AntiGravity:** install the `agy` CLI and sign in interactively once. Cere discovers models with `agy models`, streams replies and tool activity, and resumes the conversation by its own ID. `CERE_ANTIGRAVITY_BIN` overrides the executable. Headless actions requiring approval are soft-denied by the CLI unless allowed in its settings or Cere's CLI permission bypass is enabled. Cere does not change global AntiGravity configuration. Text attachments are supported; image input and interactive permission questions are unavailable in this adapter.
  Model IDs ending in an effort, such as `gemini-3.1-pro-high`, already select that effort. Use **Provider default** or the matching effort under **Model**; conflicting saved selections are rejected before dispatch. Provider failures include the CLI's error details.
- **API providers:** add a key in **Settings → Connections**, then connect to load the account's models. Select a model or enter an explicit model ID when creating a session. Standard broker environment variables also work: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, and `GEMINI_API_KEY` (or `GOOGLE_API_KEY`). Saved keys take precedence; removing one restores any environment key. Keys are stored in an owner-only file under Cere's state directory, separate from SQLite, snapshots and reviewed backups. Replacing or removing a key stops its active API turns. API usage is billed by the provider, separately from chat subscriptions.
- **Compatible endpoint:** **Settings → Connections** also takes one OpenAI-compatible chat endpoint: a base URL such as `http://127.0.0.1:1234/v1`, an optional label, and a key unless you clear **Needs a key**. Declare what it supports (tool calling, image input, streaming replies, token usage, context and output limits) and where it processes requests (this computer, your own server, a cloud service, or not sure); Cere sends only what you declare and does not verify it. That processing location decides which Workbench files and images may be sent to it. The key is kept for that endpoint's origin and is never sent to another one.
- **Saved connections:** **Settings → Connections → Saved connections** keeps more Ollama servers and compatible endpoints under names; choose one in **New session**. A conversation stays on the connection it was created on. Moving it to another connection asks you to confirm the new destination. Keys are saved per endpoint address, never in settings. The Ollama and compatible-endpoint settings above remain the defaults for new conversations.
- APIs support streaming, local conversation history, image/text attachments, optional desktop tools and Codex/Claude delegation, web search, and shared memory under the existing cloud-sharing setting. Tool availability also depends on the selected model. Requests use each provider's native API and do not follow redirects or automatically retry ambiguous failures. OpenAI responses use `store:false`. Cere keeps a bounded working context; API models without advertised context limits use a conservative 32,768-token budget. Claude API requests ask for the model's advertised output limit, or 4,096 tokens when the catalog lists none. A reply that reaches a model's output limit is kept, marked as stopped there and kept in the model's history, so you can ask Cere to continue. Model reasoning settings use provider defaults.

OpenAI, Claude API, Google AI API and Ollama requests automatically retry HTTP **429, 500, 502, 503 and 504** up to three times, waiting 1, 2 and 4 seconds plus up to 25% random jitter. `Retry-After` is honored within the request deadline and a 60-second maximum wait; a longer server requirement fails without retrying early. Other statuses, including 400/401/403/404, fail immediately. Transport failures with uncertain outcomes and streams that have already started are never replayed. **Stop** cancels pending waits. Broker retry logs contain the status, retry count and delay; cloud API conversations also show retry progress in activity. The reusable `withHttpRetry` wrapper lives in `broker/http-retry.ts`.

Use **Model** below the conversation composer to choose a model for your next message. This works within the current provider for Codex, Claude Code, AntiGravity, the API providers (including a compatible endpoint), and Ollama. Wait for the current response or press **Stop** first. The conversation, draft, attachments and CLI conversation ID stay in place; other sessions and defaults are unaffected. CLI reasoning options follow the selected model. API conversations also accept a custom model ID when the catalog is unavailable; changing models keeps readable history and recorded tool results while discarding model-specific reasoning/signatures from the working context. The new API model must support the images and tools you use. For Ollama and API conversations, the same dialog has per-conversation options: **Temperature**, **Maximum reply**, and for Ollama **Context window** and **Keep loaded**. Empty fields keep the model's defaults, and Cere sends only the options you set. From a phone, model changes are available in idle conversations that the phone started with a provider it may run: Ollama, Codex, Claude Code (with restricted mode available) and the API providers it is granted.

Protocol references: [AntiGravity headless mode](https://www.antigravity.google/docs/cli/headless/), [OpenAI Responses streaming](https://developers.openai.com/api/docs/guides/streaming-responses), [Claude Messages streaming](https://platform.claude.com/docs/en/build-with-claude/streaming), and [Google GenerateContent](https://ai.google.dev/api/generate-content). AntiGravity receives recalled memory context when cloud sharing is enabled; Cere's automatic MCP tool installation remains specific to Codex and Claude Code.

## Ollama

Run an Ollama server, then open **Settings → Connections**. The default address is `http://127.0.0.1:11434`; **Connect** accepts another HTTP(S) server or reverse-proxy base URL. **Refresh** reloads its chat models. Choose a **Default model for new conversations**, or select a model when opening each session. Pull models with Ollama itself; Cere does not download or delete models automatically. Embedding-only models are excluded and cloud-backed models are labeled **Cloud**. Cloud authentication stays with your Ollama server.

Choose **Ollama** in a new session for streaming conversation. The project folder is optional in conversation mode. The **Model** button changes an idle conversation’s model or enables assistance; existing context is retained. Defaults affect new sessions, and each session keeps its server address even if the connection setting changes. Image-capable models accept explicitly attached PNG, JPEG and WebP files (10 MB each, 20 MB combined, up to four). Thinking uses the model’s defaults and is retained in provider context without cluttering the transcript.

For orchestration, select a model marked **Tools**, enable **desktop tools and delegation**, and trust the project folder. Under **Settings → AI assistance**, enable the categories you want:

- **Provider orchestration** lets tool-enabled Ollama and API conversations start Codex or Claude tasks in the same project, send follow-ups, wait for and read results, and stop its delegated sessions. Unless a project power session grants CLI access, each task or follow-up asks you to review the exact prompt and provider first, including under Broad control. Delegated sessions appear in Sessions and retain their provider’s own approvals. Each conversation can manage only sessions it created.
- **Saved scripts** lets it list and run explicitly configured executables with their saved arguments, including other CLIs. Execution follows the same approval and grant rules as Cere’s existing script controls.
- **Tool servers (MCP)**, configured on the same page, add tools to tool-enabled Ollama and API conversations. Each server is either a program Cere starts (stdio) or a Streamable HTTP address. Every call asks first unless you allowed that tool, and a server's own hints grant nothing. Internet servers need HTTPS and public addresses; plain HTTP is only for this computer or a network you mark as local. An optional `BEARER_TOKEN` secret goes only to the server's own address, never across a redirect. OAuth sign-in is not supported. **Resources…** and **Prompts…** let you browse a server's resources and fill in its prompt templates yourself. Images that tools return become conversation files.
- Desktop categories allow application/window discovery, desktop actions, media and volume controls, timers, and approved captures. Captures require a separate sharing approval before an image-capable model receives the image, unless that session has active computer-control power access.

**Report delegated results automatically** (**Settings → AI assistance**, on by default) lets a delegated task report back by itself. When a Codex or Claude task the conversation started finishes, fails or is stopped, the conversation shows a **Delegation update** card and takes an automatic turn: the model summarizes the outcome and, if you asked for a follow-up when delegating, starts it with the result as context. When you ask for that next task up front, the model can declare it with the first one: the first approval shows it, and the update carries it even after the conversation has grown long. Starting it is a separate delegation that asks for approval like any other. A result the model already read with `sessions_wait` or `sessions_read` is not announced again. Updates that are ready together share one turn. After eight automatic turns in a row, updates wait until you send a message. Stop or an ended power session discards updates that were waiting to be reported, with a note in the conversation; after a broker restart every unfinished update becomes such a note. Nothing is replayed. Update turns neither recall nor record memory. Each update is one more model turn, which API providers bill; with the setting off, results stay in the delegated conversation until the model waits for or reads them, as before.

After Cere starts a delegated task and finishes its reply, you can keep chatting. If a result arrives during another reply, Cere reports it after that turn ends. **Stop** in the original conversation interrupts its current reply. To cancel the delegated task, open its conversation in Sessions and select **Stop**. Turning off assistance categories or pausing AI actions prevents further tool execution. Tool loops stop after 24 model responses (up to 16 requested tools per response), and a stalled HTTP request times out after three minutes. On broker restart, incomplete turns stay interrupted; unresolved tool calls are recorded as having an unknown outcome and are never replayed automatically.

Cere uses Ollama’s [native chat API](https://docs.ollama.com/api/chat) and [streaming tool protocol](https://docs.ollama.com/capabilities/streaming). Conversation content and approved attachments go to the configured server; **Cloud** models are processed through Ollama Cloud. `CERE_OLLAMA_HOST`, then `OLLAMA_HOST`, supplies the initial address when no connection has been saved. Existing installations gain these settings without a database migration.

## Web search

Enable **Settings → Knowledge → Web search** for Ollama conversations. It works in Conversation mode and Assistant mode without desktop permissions. Models with native tool support receive `web_search` and `web_read` and are instructed to use them when asked, for current facts, or when their knowledge is uncertain. Tool use still depends on the model. Check **Search web** beside the message box (**Web** in compact windows) to search first with any chat model, including models without tool support. This sends your next message as a public query, up to 500 characters; the choice resets after sending.

Choose **DuckDuckGo**, **Brave**, **Mojeek**, or **SearXNG**. The first three read public search pages without an account or API key. **Automatic** tries DuckDuckGo first, then Brave and Mojeek on failure or unusable results, and reports fallback. Selecting an individual provider keeps queries with it. For SearXNG, enter its base URL and enable `json` in its `search.formats`. Cere uses only that instance; it does not choose a random public server. Search starts disabled.

Replies include clickable source buttons; the Activity Panel shows queries, results, and errors. Public providers sometimes return CAPTCHA pages or rate limits; Cere reports these failures instead of treating a blocked page as evidence. The reader accepts public HTTP(S) HTML/text, strips scripts and navigation, and bounds page size and returned text. It checks resolved addresses and every redirect, refusing private, loopback, link-local, shared, multicast, reserved, documentation and benchmarking IPv4 ranges. It also refuses the IANA protocol-assignment block 192.0.0.0/24, including its anycast services, and the deprecated 6to4 relay range 192.88.99.0/24; the rest of 192.0.0.0/16 is public. IPv6 is limited to global unicast outside the special-purpose, 6to4 and documentation ranges. The explicitly configured SearXNG endpoint can be local. Reading a source contacts its website. Stop cancels research, and pausing AI actions or disabling search prevents further tool use. Research is limited to eight tool calls per turn. Pages and snippets are untrusted reference material.

## Shared project memory

Graph memory is integrated into the broker and native inspector. **It remains experimental:** the full reference design’s release criteria have not all passed. See [implementation status](docs/memory/implementation-report.md) and [evaluation results](docs/memory/evaluation.md) for measured results and remaining work.

Enable **Settings → Knowledge → Memory → Remember and recall conversations**. Memory starts disabled. The default extraction model is **`glm-5.3-flash:cloud`**, an Ollama Cloud model; Settings can select another. Its evaluation is in [the memory evaluation](docs/memory/evaluation.md#extraction-through-canonical-memory-ev-01). Ollama embeddings default to **`nomic-embed-text`** and require a local model registered with the configured server. Cere does not download these models automatically. Selecting Gemini embeddings and enabling cloud embedding separately allows Cere to send eligible document text and search queries to Google. Local-only passages are excluded. Cloud extraction and sharing recalled memory with a cloud chat model have independent controls. Cloud recall starts disabled, and local-only sources are excluded from cloud extraction.

Managed Codex, Claude and Ollama conversations share the same memories for the same project and memory server. Codex and Claude use the Ollama server selected in **Connections** for embeddings; existing Ollama conversations retain their saved server. Enable **Share recalled memory with Codex, Claude and cloud models** to supply recalled context to these providers. Before a turn whose message names a topic, Cere supplies bounded context when relevant memories are found. It records completed replies with their source roles. Native providers also receive the shared memory tools through Cere's session-scoped MCP connection. Standalone CLI sessions outside Cere do not automatically receive this connection. Existing project/server scope keys are preserved; changing providers does not copy or migrate the data.

Canonical observations, exact source witnesses, entities, typed assertions, correction history, episodes, and erasure records live in private SQLite at `$XDG_STATE_HOME/cere/graph-memory/memory.sqlite`. Neo4j and Qdrant are rebuildable local projections. Their pointers are checked against canonical scope, time, revision, policy, and erasure state before text is recalled. See [operations](docs/memory/operations.md) for authenticated dependency setup, Fish integration, backup, restoration, and reindexing.

**Manage project memory** opens saved notes and conversation passages for the selected conversation’s project folder and Ollama server. The **Graph, evidence and workspace inspector** adds temporal queries, provenance, structured corrections, conflicts, collector policy, indexing status, and forgetting progress. Structured corrections require an exact source quotation and the inspected revision. Uncertain effective dates remain candidates for review. Identity decisions are reversible: “same” makes recall treat two entities as one, “not the same” keeps them apart even when other links would join them, and “possible” is only a note for review. Records are never rewritten, so reverting a decision splits the entities again. Model text alone cannot establish that an action succeeded.

## Permissions and persistence

Desktop AI categories start disabled. Scoped assistance enables chosen categories and asks before sensitive tools. Broad control is optional and requires project-specific, expiring grants. Pause and revoke remain available. Cere’s grants govern its own MCP tools; they do not sandbox unrelated shell access already granted to a CLI.

**Permissions** opens a single center for effective access, provider state, project grants, expiry, revocation, and separate controls for pausing Cere actions and stopping provider work. **Settings → AI assistance** also has two switches that stay on until you turn them off. **Skip CLI permission prompts** approves project trust, commands, file changes, scripts and delegation in managed conversations, and auto-approves CLI requests from paired phones that hold both `providers.execute` and `approvals.provider` (see [mobile security](docs/mobile/SECURITY.md)). It also starts new `cere terminal` sessions with `--dangerously-bypass-approvals-and-sandbox` (Codex) or `--dangerously-skip-permissions` with the sandbox disabled (Claude Code). **Skip computer permission prompts** approves desktop actions. Questions always require an answer. Neither switch approves Workbench change reviews, image jobs, analysis runs, exports or vision-helper requests. Only the Workbench's own permissions skip those questions (see [Workbench](#workbench-files-images-and-analysis)).

**Power sessions** deliberately grant CLI full access, computer control, or both to selected idle, locally managed sessions in one canonical project directory. Leases last 1–120 minutes, remain visible, are never persisted, and must be renewed deliberately. Temporary, remote, and linked sessions cannot start one. Ending or expiring a lease revokes new authority immediately and stops owned provider work, reporting confirmed or unconfirmed termination. Leases do not reach linked terminals, which keep their own permission configuration unless launched while **Skip CLI permission prompts** is on.

CLI full access can control the desktop through shell commands. Cere’s desktop permission categories do not contain unrestricted CLI processes. **Pause Cere actions** blocks Cere tools; **Stop provider** interrupts provider work. External provider or administrator restrictions still apply. Editing a saved executable invalidates review of its previous definition.

Markdown renders during streaming and when stored sessions reopen. Message Copy preserves the original Markdown, without memory citations while they are hidden; text selection copies the rendered text. Provider approvals remain separate from Cere’s desktop approvals. URL requests show the destination and require explicit browser opening and confirmation. Other complex forms are declined with an explanation. The adapters are checked against the [Codex app-server protocol](https://learn.chatgpt.com/docs/app-server) and [Claude Code headless mode](https://code.claude.com/docs/en/headless). They were last validated with Codex 0.162.1 and Claude Code 2.1.296 on October 12, 2026. On October 20, 2026 the no-cost checks `node tools/check-codex-protocol.ts` (every app-server method Cere uses is in the installed binary's schema) and `node tools/check-claude-protocol.ts` (Cere's ordinary and restricted print-mode flags and the stream-json handshake) passed for Codex 0.163.0 and Claude Code 2.1.303; they check names and handshakes, not turn behavior. Cere requires Codex 0.158.0 or newer and Claude Code 2.1.259 or newer, and reports an older CLI as needing an update. Authentication and billing remain with each CLI.

State is stored in `$XDG_STATE_HOME/cere/cere.sqlite` (normally `~/.local/state/cere`), using private filesystem permissions. It includes settings, drafts, conversation messages, recent action metadata, and timers. Screenshots live in the sibling `captures` directory. Workbench conversation files are stored by content hash under `artifacts/` in the state directory, and private conversation workspaces under `workspaces/`. Codex and Claude transcripts remain in their native locations. Ollama’s full conversation context, tool results, and explicitly shared images are stored in Cere’s private database. Enabled graph memory also publishes eligible projections to the configured local Neo4j and Qdrant services; selected cloud extraction uses Ollama Cloud.

Cere IPC uses a private Unix socket at `$XDG_RUNTIME_DIR/cere/broker.sock`; enabled Fish collection uses `$XDG_RUNTIME_DIR/cere-memory/memory.sock`. Connections require the same OS user. Cere opens no TCP listener by default. The optional Android companion gateway listens only on explicitly selected LAN/WireGuard addresses, for a paired phone or for the five minutes a pairing QR is shown (when it accepts only that offer's signed answer); pairing is confirmed locally by comparing six words. See [mobile setup](docs/mobile/SETUP.md) and [implementation limits](docs/mobile/TESTING.md). Configured Ollama and memory dependencies use HTTP(S) or Bolt, with the packaged database ports restricted to loopback. MCP subprocesses receive session-scoped random capability tokens. A UI restart leaves broker work running. A broker restart marks incomplete turns interrupted and never silently replays them. Stopping the broker refuses new changes, lets running phone operations finish, then stops providers, workers, memory and speech within ten seconds; a stop that could not confirm all of that is reported in Health after the next start. If the broker stays connected but stops answering, the interface shows **Cere is not responding** after 15 seconds, ends the requests it was waiting on with an explanation instead of resending them, keeps your drafts, and recovers when the broker answers again. Restart the installed broker with `systemctl --user restart cere-broker` only when you intend to interrupt its active work.

For isolated development, set `CERE_STATE_DIR` and `CERE_RUNTIME_DIR`. Set `CERE_CODEX_BIN` or `CERE_CLAUDE_BIN` to an executable path when testing a different provider build. Managed conversations, provider detection, model catalogs and Codex history import all use that executable; `cere terminal` still runs the CLI found on `PATH`. Without an override, the broker looks on `PATH` and then in `~/.local/bin`, where both CLI installers put their launchers, and adds `~/.local/bin` to the `PATH` its provider processes inherit.

Set `CERE_CAGE_BINARY` for a project-local Cage build; the [validation record](VALIDATION.md) includes the setup used here. It isolates every command from the working desktop and configures locally extracted Qt dependencies when present. Offscreen UI runs use virtual outputs at several scales. Use `tools/test-virtual-desktop.sh ./build/cere-ui-check SLOT` for compositor checks, including layer-shell placement and pointer interactions. The `workbenchAcceptance` slot drives the Workbench end to end: browsing, preview and editing, a reviewed change and its undo, images and the editor, runs, the shelf, the `@` picker, and the compact sheet. Pointer events go to a private Wayland seat, without physical input devices. Services such as Spotify and Satty need fixtures inside that private session; never redirect checks to the working desktop. Captures from `/tmp/cere-ui-evidence` are retained in the wrapper's evidence directory under `tmp/cere-ui-evidence`. After a full catalog run, `env CERE_TEST_AVATAR=alia` before `./build/cere-ui-check` limits avatar loops for focused artwork rechecks; pointer checks also retain their Cere baseline.

After `cmake --build build --target cere cere-screenshots`, `tools/screenshots/run.sh` regenerates the documentation images in [`screenshots/`](screenshots/README.md) from a scripted demo profile. It renders offscreen inside private user, mount, process and network namespaces, so it uses no real Cere profile, compositor, provider account or network. Name capture slots, such as `settingsPages`, to retake only those images.

After `python3 tools/install-user.py --prefix DIR` (which touches no session), `node tools/check-install.ts DIR [commit]` confirms the staged install has every broker, QML, asset, protocol and shell-hook file, the runtime packages, native modules, speech engine, launchers, service unit and a clean build identity.

`tools/live-check.ts` runs real provider calls in a temporary project, including a named harmless printf script, approval, another turn, and a process disconnect/resume. It consumes normal CLI usage. Run it only with isolated `CERE_STATE_DIR` and `CERE_RUNTIME_DIR` values. `tools/probe-providers.ts` is a smaller no-tool connectivity check.

`node tools/check-ollama.ts MODEL [codex|claude]` exercises real Ollama conversation, recall after disconnect, an approved saved `printf` command, and optional provider delegation. It creates its own isolated broker/project, uses normal provider usage, and prints the evidence directory containing `report.json`, `broker.log`, and the test database. Only the known test command and exact test delegation are approved. Backend tests and native UI checks use local Ollama fixtures with no inference usage.

The avatar source art, transparent extractions, eyelid edits, gesture sheets, portraits and built-in imagegen prompts are kept outside the repository. Optional `sheetLandmarks` in the local source registry supplies sixteen normalized eye positions per route, plus `closed` for authored closed-eye poses. Witty uses these to distinguish her visible eye from mint hair and the fixed X mark; closed blush artwork remains intact. Reviewed `heldEyes` ellipses locate eyelids in the final registered gesture frames; `heldEyeSource` can refine the neutral eyelid crop. A `closed` pose remains exact, and a null eye preserves an eye that is already shut or covered. `node tools/prepare-avatar-poses.mjs --blink-only` updates only those existing packed blink cells, preserving every open frame and rig. Run it through the virtual desktop wrapper and review the resulting eye crops. The retired sprite/cutout assets and their preparation tools have been removed. Desktop branding retains `assets/cere-emblem.png`; `tools/prepare-icons.mjs` generates launcher icons, and its prompt is kept with the source art.

Standing gestures register each complete drawing against the neutral head and sole anchors before interpolation, with one affine map shared by the torso, hips and legs. The pose baker tracks the head across the route, smooths sudden shifts between keys and matches material colors to the neutral drawing. Held eyelid landmarks anchor the smoothed path. Size correction preserves authored head tilt so long hair cannot fold where the head meets the body. Neither keyframes nor inbetweens paste neutral lower legs onto a differently sized torso. All avatars use connected-figure extraction to exclude sheet rules and stray pixels. Pickup keeps its suspended artwork and free feet. Interpolation blends temporal alpha independently of optical-flow confidence, so an old limb fades when its correspondence leaves the canvas. Portrait expressions reuse the neutral silhouette, hair and costume outside the face.
