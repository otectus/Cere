# Graph memory architecture

Graph memory runs inside the Cere broker. `MemoryService` owns network clients and collectors; a worker thread owns `Canonical` and its single SQLite writer. The UI and CLI use the existing private broker socket. Linux `SO_PEERCRED` enforces same-user connections through the compiled `cere-peercred.node` helper.

SQLite is authoritative. Its strict schema contains source observations, exact Unicode-span witnesses, scoped entities and aliases, identity decisions, fact slots, bitemporal assertion versions, event streams, episodes, topics, artifacts, lineage, commits, projection jobs, response provenance, and erasure records. Versioned schema checksums are verified before serving. WAL, FULL synchronous commits, foreign keys, and secure deletion are enabled. Changing the schema requires a migration; editing an already-applied migration fails closed.

Every canonical mutation obtains a monotonic revision and transaction timestamp. It writes its effects, FTS document changes, and ordered projection jobs in the same transaction. Read tokens make affected canonical artifacts available independently of projection catch-up. Neo4j stores reified assertion nodes and evidence relationships. Qdrant stores immutable vectors and typed metadata, not canonical text. A delayed or stale projection cannot authorize a fact: every candidate is hydrated and checked against SQLite.

Assertion validity and the revision at which Cere knew an assertion are separate half-open intervals. A correction closes a prior knowledge version, creates its surviving world-time intervals, and records the replacement. Unknown dates are not invented. Single-valued equal-authority disagreements become disputed. Multivalued corrections require a specific member. Exact supporting evidence and its trust class accompany every claim; assistant prose cannot establish an instrumented outcome.

Retrieval combines exact aliases, FTS5, vector candidates, and bounded relationship expansion, then rank fusion and optional graph ranking. Scope, temporal applicability, policy, erased state, evidence, and content revisions determine eligibility. Context includes coverage, snapshots, evidence IDs, and budgets. Ollama receives it as delimited data. Policy changes and erasures invalidate in-flight packets and gate late output.

Erasure writes an fsynced external registry before suppression, traverses content lineage, scrubs canonical copies, and queues deletion across projection generations. Source-specific deletion can rederive an assertion from independent surviving witnesses. Explicit fact deletion includes its supporting occurrences. A receipt distinguishes immediate suppression from completed physical purge; unavailable dependencies keep purge pending. Restoration uses the current registry before rebuilding projections.

The collector runtime is transient and uses source epochs, sequence ordering, monotonic freshness, and explicit unknown states. Fish reports structured status and approved CWD metadata without command text. Hyprland observes window metadata with titles disabled by default; Kitty uses only a configured read-only inspection endpoint. Repository metadata verifies checkout roots. Refer to [implementation status](implementation-report.md) for incomplete task/identity and desktop lifecycle behavior; the presence of schema tables does not mean every reference workflow is complete.
