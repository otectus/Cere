# Desktop services gate

W14 of the desktop and mobile review: each secondary desktop service has a fixture gate that runs in `npm test` (inside `tools/test-virtual-desktop.sh` for anything that touches the desktop), and, where a fixture cannot reach the behavior, a harmless installed-system check or an explicit limitation. This is a completion gate, not a list of defects. A row is **gated** when its listed tests run in the ordinary suite; **installed check** names a command to run on the target system; **limitation** says what no automated check here covers.

| Area (W14 item) | What must hold | Fixture gate | Installed check | Limitation |
| --- | --- | --- | --- | --- |
| Speech and audio (1) | Missing/disconnected devices, engine unavailable, empty input, interruption, Stop, provider mute, queue order, fallback, no replay on reconnect, recording cleanup | `tts.test.ts` (missing Piper/audio devices; stalled dispatcher; Stop kills owned player; provider mute; no replay of an accepted dispatcher message), `audio-devices.test.ts` (missing chosen device fails before playback; a new speaker stops speech without replaying), `indextts.test.ts` (cancel releases the worker; crashes, malformed IPC and OOM have stable codes), `elevenlabs.test.ts` (no retry of a broken stream; abort on switch), `pinned-replies.test.ts` (phone-turn replies are not read aloud) | `tools/test-virtual-desktop.sh` with a private PipeWire, as `desktop-services.test.ts` does; opt-in `indextts-integration.test.ts` with IndexTTS installed | Bluetooth output changes need real hardware. |
| Transcription and voice commands (2) | Permission/device failure, long-file cancel, model availability, no auto-submit or execution | `transcription.test.ts` (one microphone owner; cancel deletes audio; missing configuration visible; recording limit; imported recordings leave no audio), `voice-commands.test.ts` (whole-phrase allowlist only, off by default, never answers approvals) | — | Foreground/background priority on the target machine is measured, not asserted. |
| Extensions and custom tools (3) | Startup/crash/timeout, stale schema, malformed and bounded output, secret redaction, changed definitions, allowlists, cancellation of owned subprocesses | `extensions.test.ts` (validation, Stop cancels, crashes quarantined, turning off revokes, bounded untrusted output), `custom-tools.test.ts` (fixed templates, credentials only to their origin, one program without a shell, changes revoke) | — | — |
| Workflows, capsules, verification (4) | Exact reviewed recipe/version, parameter validation, provenance, stale checks after edits, partial failure, provider success vs verified success | `workflows.test.ts` (immutable versions and typed inputs; RC-04 stale after edits; M17 only current observed passes count), `workspace.test.ts` (result verification rejects changed definitions), `remote.test.ts` (phone sees provider outcome apart from verification) | — | — |
| Schedules and timers (5) | Timezone/DST, invalid dates, missed occurrences, overlap, restart after claim, permission/config change, disabling, no catch-up duplicates | `schedules.test.ts` (deterministic across DST; runs once across a restart; missed/overlapping/changed occurrences reported and not run; a change pauses until reviewed), `remote.test.ts` (phone pause only) | — | Machine suspend is simulated by missed occurrences, not by suspending the host. |
| Vault and collections (6) | Symlinks, inaccessible files, external edits, removed sources, local-only rules, incremental and cancelled indexing, cloud policy | `knowledge.test.ts` (M06 indexes only permitted files and reindexes with erasure; RC-01 vault privacy rules; page reading blocks local addresses), `knowledge-collections.test.ts` | `node tools/check-knowledge.ts` | — |
| Telemetry (7) | Fish/Zsh hooks, Kitty mapping, symlinked projects, worktrees, repository changes, deleted paths, event storms, suspend/resume, no invented working directory | `telemetry.test.ts` (canonical roots and symlinks; inotify rename/deletion; worktree HEAD; malformed data rejected), `telemetry-shells.test.ts` (Fish, Bash and Zsh hooks), `telemetry-persistence.test.ts`, `workspace.test.ts`, `remote.test.ts` (phone card reports only fresh, in-project state) | `node tools/benchmark-telemetry.ts` | Kitty remote-control and suspend/resume need the working desktop; not exercised here. |
| Persistence and recovery (8) | Migration from older versions, insufficient space, unwritable directories, crash during transaction/backup/restore, corruption diagnosis, replay protection, temporary-conversation non-persistence, erasure registry preservation | `memory-migration-backup.test.ts` (S4 no backup room, unwritable directory, disk filling mid-copy, restored backup keeps later forgetting), `memory-migrations.test.ts`, `recovery-races.test.ts` (consistent snapshots, stale activation rejected, in-flight mutations refused), `broker-restart.test.ts` (restart, SIGTERM during work, stale socket), `workspace.test.ts` (temporary conversations never persist), `remote.test.ts` (accepted operations become unknown after restart) | `tools/test-virtual-desktop.sh npm test` | Migration from each distributed release is covered by the migration fixtures, not by installing old packages. |
| Absent optional service (9) | A missing speech engine, graph projection, terminal endpoint or media tool degrades only its feature | `degraded-services.test.ts` (memory failing, workspace awareness down, speech off and no desktop tools on PATH: chat completes, Health names what is missing), `core.test.ts` (memory deadline), `shared-memory.test.ts`, `desktop.test.ts` (dependency diagnostics) | Desktop Health → "Unavailable until installed" | — |

Restart and cancellation release processes and files: `tts.test.ts` (owned Piper/player reaped on Stop), `indextts.test.ts` (worker exits on cancel and idle unload), `transcription.test.ts` (owned audio removed), `extensions.test.ts` (Stop cancels calls), `shutdown.test.ts` and `broker-restart.test.ts` (ordered shutdown confirms owned work). Background work stays bounded: `jobs.test.ts` (foreground yield without leaking listeners), `fanout.test.ts` (bounded delivery to slow clients).
