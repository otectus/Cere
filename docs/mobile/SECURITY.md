# Mobile security boundary

The default desktop opens no Cere TCP listener. Mobile access is an opt-in TLS gateway inside the existing broker; same-user Unix IPC remains separate. Pairing is offline and locally approved. Android is an untrusted remote principal even on a private LAN. There is no generic Core RPC, shell, settings patch, graph-admin forwarding or network pairing endpoint.

Device authority is the intersection of exact canonical project paths, pinned Ollama hosts, capabilities, ordinary desktop categories and explicitly approved saved-script IDs. Each device expires after 90 days unless renewed locally. Changing grants invalidates live sessions and command-result visibility. Native Codex execution uses restrictive policy and approval prompts. Claude execution requires a detected CLI with `--restricted`, `--strict-mcp-config`, and manual permission handling. Remote Claude ignores user/project/local settings, confines file tools to the approved working directory, and loads only the Cere MCP configuration; Bash, other code-running built-ins, and WebFetch are unavailable. Unsupported Claude versions remain read/Stop/Deny only. Native capture-sharing Allow remains unavailable without immutable media ingestion.

The desktop CLI bypass switch automatically allows CLI/provider permission requests in remote-origin sessions and delegated children only when the device has both `providers.execute` and `approvals.provider`. Questions still require answers. Device scopes, Pause, restricted native launch policy, and computer permissions remain enforced; the CLI switch does not grant additional tool categories or remove the native sandbox. Provenance is sticky; desktop involvement cannot silently upgrade those sessions. Pause, Stop, device revocation and gateway shutdown recheck/abort work at asynchronous boundaries, invalidate provider generations and close native processes. Previously completed external effects cannot be undone; an ambiguous effect is reported as unknown and is not retried.

Files are canonicalized beneath granted roots; scripts are predefined immutable executable/argv/cwd/timeout definitions reviewed by digest. Media commands retain the reviewed MPRIS target. Discovery requires the same category authority as execution. Model catalogs/defaults are withheld if their host/native execution authority is absent. No provider credentials or MCP tokens are returned to phones.

Android backup/device transfer is disabled. Private cache/media use AES-GCM with a Keystore key, and signing keys are non-exportable. Forget/revocation removes state, images and Keystore aliases. Notification content is private and lock-screen copies are redacted; tapping a request opens it in the app's Inbox, where authority-expanding actions require explicit review. Each request alerts once; a changed request alerts again. Biometric-mode devices additionally authenticate each such action; desktop-approved trusted devices sign silently with their separate non-exportable action key. Exact `sessions.send` commands are the sole proof-required exception: when welcome advertises `sendAuthentication: "connection-key"`, the background connection key signs the same challenge-bound method, parameter digest and command ID without a password or fingerprint prompt. The action key remains valid for legacy Send and mandatory for every other proof-required mutation. Its Android authentication requirement is selected by the desktop in the signed pairing offer (`actionAuthentication`); trusted mode never extends the connection key to other actions. Legacy records/offers default to biometric, and Android refuses trusted actions unless its stored policy matches the authenticated welcome. A missing welcome field means the older action-key behavior, not permission to send unsigned. No cleartext, broad storage, accessibility service, overlay or install-packages permission is requested. Markdown HTML is literal; remote images are never fetched automatically. Camera access is requested only for the pairing QR scanner or when the person chooses Camera. A full-size capture is written to a private app-cache file that the camera app receives through a non-exported FileProvider grant; it is re-encoded into the encrypted store without metadata and deleted. Shared images are imported only from `content://` URIs. Debug builds are debuggable and meant for local testing; development snapshots use the non-debuggable, R8-optimized `dev` build type. The desktop can load a phone's public pairing response from a local file; it reads at most 16 KiB and keeps only the `cere-pair://v1/` response.

The desktop gateway applies no time-based rate limits to reconnects, reads, signed actions, native-history refreshes or memory operations. It caps simultaneous sockets, pending challenges, in-flight work, authentication time, buffered output and media quotas. Incoming pre-authentication messages are rejected above 8 KiB; the WebSocket receiver still has a 1 MiB allocation ceiling shared with authenticated messages, bounded to ten sockets. This is a documented difference from the plan's proposed separate pre-auth receiver allocation cap. Memory operations are serialized per device and remote graph closures preflight a conservative whole-store budget inside the worker. Busy operations return `SESSION_BUSY`; capacity limits return `LIMIT_EXCEEDED`. Larger stores remain usable locally.

Retention: command results 30 days with persistent ID/digest tombstones; audit records 90 days; reference-only event journal 24 hours/10,000 events. Revocation purges media after owned work is stopped. Memory erasure invalidates transcripts/cache epochs and strips old command results so command recovery cannot reintroduce forgotten text. No claim is made to erase copies already sent to external providers or separately exported by the owner.

Independent implementation review found and drove fixes to signature canonicalization, post-accept uncertainty, grant-scoped command recovery, native process cancellation, media immutability/quotas, memory work budgets, cache erasure and locked-state handling. This review is not a penetration-test certification or physical-device validation. [TESTING.md](TESTING.md) records remaining release gates. Automatic certificate/key rotation is not implemented; locally reset and re-pair all devices when necessary.

Replacement offers bind the prior device ID, desktop identity, and authentication mode. Confirmation derives mode from the stored signed offer and atomically revokes the old record. Exact project IDs are reused where paths match. Endpoint renewal is local-only, requires explicit confirmation, retains TLS/signing keys, invalidates outstanding offers, and requires replacement pairing for the renewed certificate. Phone migration preserves encrypted local work and refuses unresolved operations.

Network availability is separate from authority: losing an interface removes that listener but retains the enabled preference and retries. It does not cancel accepted work. Disable, revoke, expiry, and scope changes still enforce authority independently of reachability.
