# Mobile security boundary

The default desktop opens no Cere TCP listener. Mobile access is an opt-in TLS gateway inside the existing broker; same-user Unix IPC remains separate. Pairing is offline and locally approved. Android is an untrusted remote principal even on a private LAN. There is no generic Core RPC, shell, settings patch, graph-admin forwarding or network pairing endpoint.

Device authority is the intersection of exact canonical project paths, pinned Ollama hosts, capabilities, ordinary desktop categories and explicitly approved saved-script IDs. Each device expires after 90 days unless renewed locally. Changing grants invalidates live sessions and command-result visibility. Native Codex execution uses restrictive policy and approval prompts. Claude execution requires a detected CLI with `--restricted`, `--strict-mcp-config`, and manual permission handling. Remote Claude ignores user/project/local settings, confines file tools to the approved working directory, and loads only the Cere MCP configuration; Bash, other code-running built-ins, and WebFetch are unavailable. Unsupported Claude versions remain read/Stop/Deny only. Native capture-sharing Allow remains unavailable without immutable media ingestion.

Local CLI/computer bypasses do not apply to remote-origin sessions or their delegated children. Provenance is sticky; desktop involvement cannot silently upgrade those sessions. Pause, Stop, device revocation and gateway shutdown recheck/abort work at asynchronous boundaries, invalidate provider generations and close native processes. Previously completed external effects cannot be undone; an ambiguous effect is reported as unknown and is not retried.

Files are canonicalized beneath granted roots; scripts are predefined immutable executable/argv/cwd/timeout definitions reviewed by digest. Media commands retain the reviewed MPRIS target. Discovery requires the same category authority as execution. Model catalogs/defaults are withheld if their host/native execution authority is absent. No provider credentials or MCP tokens are returned to phones.

Android backup/device transfer is disabled. Private cache/media use AES-GCM with a Keystore key, and signing keys are non-exportable. Forget/revocation removes state, images and Keystore aliases. Notification content is private/redacted; its review activity performs fresh authentication for authority-expanding actions. Exact `sessions.send` commands are the sole proof-required exception: when welcome advertises `sendAuthentication: "connection-key"`, the background connection key signs the same challenge-bound method, parameter digest and command ID without a password or fingerprint prompt. The action key remains valid for legacy Send and mandatory for every other proof-required mutation. A missing welcome field means the older action-key behavior, not permission to send unsigned. No cleartext, broad storage, accessibility service, overlay or install-packages permission is requested. Markdown HTML is literal; remote images are never fetched automatically.

The gateway caps sockets, authentication time, reads, signed actions, buffered output and media quotas. Incoming pre-authentication messages are rejected above 8 KiB; the WebSocket receiver still has a 1 MiB allocation ceiling shared with authenticated messages, bounded to ten sockets. This is a documented difference from the plan's proposed separate pre-auth receiver allocation cap. Memory operations are serialized per device and remote graph closures preflight a conservative whole-store budget inside the worker. Larger stores fail closed with `LIMIT_EXCEEDED` and remain usable locally.

Retention: command results 30 days with persistent ID/digest tombstones; audit records 90 days; reference-only event journal 24 hours/10,000 events. Revocation purges media after owned work is stopped. Memory erasure invalidates transcripts/cache epochs and strips old command results so command recovery cannot reintroduce forgotten text. No claim is made to erase copies already sent to external providers or separately exported by the owner.

Independent implementation review found and drove fixes to signature canonicalization, post-accept uncertainty, grant-scoped command recovery, native process cancellation, media immutability/quotas, memory work budgets, cache erasure and locked-state handling. This review is not a penetration-test certification or physical-device validation. [TESTING.md](TESTING.md) records remaining release gates. Automatic certificate/key rotation is not implemented; locally reset and re-pair all devices when necessary.
